# 문경관광공사 공직비위 익명신고센터

문경관광공사(Mungyeong Tourism Corporation)의 **내부 공직비위 익명신고** 웹사이트입니다.
임직원 및 수탁 관계자의 부정·비리·갑질·이해충돌 등을 익명으로 접수하고,
신고번호로 처리결과를 확인할 수 있도록 구성한 **완전 오리지널 디자인**의 정적 프런트엔드입니다.

> 이 프로젝트는 특정 외부 기관의 사이트를 복제한 것이 아니라, 문경관광공사 자체 브랜딩으로 새로 제작되었습니다.

## 구성

| 페이지 | 설명 |
|--------|------|
| `index.html` | 센터 소개 · 익명성 안내 · 신고 범위 · 처리 절차 |
| `report.html` | 신고 접수 폼 (유형·내용·증빙 첨부·비밀번호 설정, 신고번호 발급) |
| `result.html` | 신고번호 + 비밀번호로 처리결과 조회 |
| `faq.html` | 자주 묻는 질문 (아코디언) |
| `css/style.css` | 공통 스타일 (문경 숲 컬러 테마, 반응형, 접근성) |
| `js/common.js` | 내비게이션·FAQ 공통 스크립트 |
| `js/report.js` | 신고 접수 폼 검증 및 신고번호 발급 로직 |

## 로컬 미리보기

```bash
# 저장소 루트에서
python3 -m http.server 8080
# 브라우저에서 http://localhost:8080 접속
```

## ⚠️ 운영 배포 시 반드시 구현해야 할 사항 (보안)

현재 코드는 **프런트엔드(화면/UX) 데모**입니다. 익명신고는 신고자 보호가 핵심이므로,
실제 운영 전에 아래 백엔드 보안 요소를 반드시 갖추어야 합니다.

1. **서버 측 암호화 저장** — 신고 내용·첨부파일은 전송 구간(HTTPS) 및 저장 구간에서 암호화되어야 합니다. 현재 `report.js`는 내용을 서버로 전송하지 않습니다(데모).
2. **접속 정보 비수집 보장** — 웹서버 액세스 로그에서 신고 경로의 IP·User-Agent 기록을 제외하거나 익명화하세요. 화면 문구("IP 미수집")가 실제 서버 설정과 일치해야 합니다.
3. **신고번호·비밀번호 검증** — 신고번호는 서버에서 발급·저장하고, 비밀번호는 해시(bcrypt 등)로 저장하여 조회 시 서버에서 검증해야 합니다.
4. **첨부파일 메타데이터 제거** — 업로드 파일의 EXIF 등 신고자 식별 가능 메타데이터를 서버에서 제거하세요.
5. **접근 통제·감사로그 분리** — 신고 열람 권한을 최소 인원으로 제한하고, 관리자 활동 로그와 신고자 정보를 분리 관리하세요.
6. **법적 고지 검토** — 「공익신고자 보호법」 등 관련 법령 문구와 개인정보 처리방침을 법무/감사 부서가 검토해야 합니다.

조직의 상황에 맞는 백엔드(예: 암호화 DB + 관리자 콘솔) 연동이 필요하시면 이어서 도와드릴 수 있습니다.
